# `pl2303_usb` Theory of Operation (TOO)

## Architecture Overview

The `pl2303_usb` component exposes a Prolific PL2303 USB vendor class interface over ESP32-S3 native USB-OTG hardware using Espressif's `esp_tinyusb` v2.0+ driver.

```mermaid
graph LR
    Host[USB Host / Head Unit] <-->|EP 0x02 Bulk OUT| TinyUSB[TinyUSB Stack Core 1]
    TinyUSB -->|tud_vendor_rx_cb| TaskNotify[xTaskNotifyGive]
    TaskNotify --> BridgeTask[usb_espod_bridge_task]
    BridgeTask -->|pl2303_usb_read_bytes| espod[esPod Ingestion]
    espod -->|usb_tx_handler| WriteBytes[pl2303_usb_write_bytes]
    WriteBytes <-->|EP 0x83 Bulk IN| Host
```

### 1. Vendor Control Requests (`tud_vendor_control_xfer_cb`)
- Handles Prolific vendor-specific control transfers (bRequest `0x01` setup reads/writes, `0x20` SET_LINE, `0x21` GET_LINE, `0x22` SET_CONTROL).
- Drives DTR and RTS signal levels via GPIO bitbanging (`CONFIG_DTR_PIN`, `CONFIG_RTS_PIN`).

### 2. Event-Driven USB Bulk OUT Ingestion
- When USB Host writes data to Bulk OUT endpoint (`0x02`), TinyUSB invokes callback `tud_vendor_rx_cb(idx, buffer, bufsize)`.
- `tud_vendor_rx_cb` checks if `s_rx_task_handle` is registered via `pl2303_usb_set_rx_task_handle()`.
- If set, `xTaskNotifyGive(s_rx_task_handle)` unblocks `usb_espod_bridge_task` instantly.
- `usb_espod_bridge_task` calls `pl2303_usb_read_bytes()` to drain endpoint FIFO and passes raw bytes to `espod.processRawBuffer()`.

### 3. Bulk IN Transmission (`pl2303_usb_write_bytes`)
- Outbound responses generated by `esPod` call `pl2303_usb_write_bytes()`.
- If vendor endpoint is mounted and not busy (`!usbd_edpt_busy(0, CONFIG_EP_VENDOR_BULK_IN)`), data is queued for transmission via `usbd_edpt_xfer()`.
